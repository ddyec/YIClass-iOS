# Project working preferences

- Build and deliver only iPhone/iPad device IPA packages. The user has no simulator and explicitly does not want simulator packages.
- Do not run `scripts/package-build.sh simulator`, generate or upload simulator distribution artifacts, or trigger simulator-only review workflows unless the user explicitly asks for them.
- Keep automatic downloadable builds device-only. Normal core tests and compile checks can still run where appropriate.
- Use the current folded-book product logo for product branding and the app icon. Do not reintroduce the old YC mark. Replace legacy YC branding with the normal current book logo including its original background. Use the existing transparent AssistantLogo for AI-related entry points, including the floating AI button and the AI drawer page, with black strokes in light mode and white strokes in dark mode (follow the effective app color scheme, not the accent color).
- Use a real UITabBarController with default iOS 26 Liquid Glass and native onScrollDown minimization. Keep the separate trailing AI entry through UISearchTab with the existing logo; veto its selection using the public tab delegate to open the assistant drawer and preserve the current page. Let UIKit own shape, selection lens, gestures, animation and safe-area reservation. Do not draw another bottom bar, layer glass effect views, or apply custom bar/selection backgrounds. Use the user's theme.accent for selected icons.
- In the collapsed week grid, maximize daytime course space up to the actual top of floating navigation; measure global frame overlap instead of subtracting the entire navigation height again. Keep “展开晚间” visible without scrolling. Once expanded, put “收起晚间” at the end of the vertical course content and allow it to scroll behind navigation, with enough bottom scroll space to bring it above navigation for tapping. Expansion adds rows without shrinking daytime rows.
- Main navigation has three destinations (schedule, todos, settings) plus a separate AI button opening a conversation drawer. The empty assistant shows only the logo and “我们应该安排什么？”, with close at top left and history at top right.
- Todo header shows “待办” on the left and a date button on the right opening a calendar. Put this header in the page layout so toolbar overflow cannot replace it with an ellipsis. Make the pending section the main visual focus with a larger header and empty-state area. Completed tasks must be collapsed by default. Preserve urgency-colored task backgrounds with text status labels.
- Very long week-card course names should truncate to leave room for the classroom. Keep the full course name available by opening the course.
- Lock-screen Live Activities show course/task titles, times and course locations. The current Live Activity redesign allows type icons/colors and a bounded countdown for one-item cards. Omit dates/count headers, action rows and decorative outlines. The current follow-up allows native timer progress bars in the expanded island, split by actual teaching periods with break/end labels. Keep up to two courses aligned, with internal padding and a compact fallback for constrained presentations; do not force an oversized minimum height.

- Automatic Actions use one ordered pipeline: Test first, then Build IPA only after Test succeeds. Do not duplicate automatic test/build runs across workflows. Link the versioned IPA artifact directly in the final build summary; do not run another test job after packaging.
- AI book strokes must remain clean vector paths with open counters. Do not thicken the bitmap with repeated shadows. Inspect small-size light/dark renderings before delivery.
- Visual checks may use a macOS SwiftUI ImageRenderer for the production card view; distinguish these from real iOS WidgetKit or device screenshots.

- The 3.2.1 custom stacked UIGlassEffect implementation failed human visual review (rectangular bar and selection). Keep the replacement native; do not attempt to reproduce the tab bar lens with custom materials or rely on default corners of arbitrary effect views.

- Day agenda tasks and placements are canonical in day-agenda.json; retain stable UUIDs on migration and do not copy timetable courses into that document. Deadline is separate from scheduled work time. Show overlaps in lanes, and preserve atomic task/placement edits, backup/recovery, undo and stale-AI rejection.
- Keep Actions ordered Test -> Build IPA. Review production timeline, task cards and task widget renders before sharing the device package.

- For the current navigation fix, the user chose on-device human visual review after CI simulator startup stalled. Keep the automatic pipeline Test -> Build IPA; do not gate device delivery on simulator UI checks. Only deliver the device IPA.

- Live Activity follow-up: shorten the compact resident Dynamic Island capsule; expanded size is acceptable. Use the native leading/trailing expanded regions for title/timer and bottom for time/location and per-period progress, rather than putting the entire card in the bottom region. Use one type icon without duplicate course/task headings, place the countdown on the right, and keep content inset and clipped to bounds. Provide a Settings style-test screen with idle/upcoming/ongoing/ending states and an explicit countdown start. Prioritize phone acceptance; do not add simulator runs or repeated visual-render work.

- Preserve the current small expanded-island size. Use native expanded horizontal content margins for the large capsule arcs; never enlarge the island to fix overflowing text. Bound the title to two readable lines with tail truncation and full accessibility text, protect the icon, keep locations to one line, and bound progress height for long course blocks. The phone preview uses a capsule rather than a mild rounded rectangle.
